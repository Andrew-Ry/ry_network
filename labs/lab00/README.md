# Лабораторная работа: Базовая настройка коммутатора

## Цель работы

Выполнить базовую настройку коммутатора Cisco Catalyst 2960, настроить локальный и удалённый доступ к устройству, назначить IP-адрес управления и проверить сетевую связность между коммутатором и рабочей станцией.
---
## Топология

В лабораторной работе используется следующая топология:

```text
             Console
        ┌───────────────┐
        │               │
        │               ▼
┌─────────────┐     ┌─────────────┐
│     S1      │     │    PC-A     │
│ Cisco 2960  │     │             │
│             │     │192.168.1.10 │
└──────┬──────┘     └──────┬──────┘
       │ Fa0/6              │ NIC
       └────────────────────┘
              Ethernet

S1 VLAN 1: 192.168.1.2/24
```
## Таблица адресации

| Устройство | Интерфейс | IP-адрес | Маска |
|---|---|---|---|
| S1 | VLAN 1 | `192.168.1.2` | `255.255.255.0` |
| PC-A | NIC | `192.168.1.10` | `255.255.255.0` |

PC-A подключён к интерфейсу `FastEthernet0/6` коммутатора S1.

# Задачи

В ходе лабораторной работы необходимо:

1. Проверить исходную конфигурацию коммутатора.
2. Выполнить базовую настройку коммутатора.
3. Настроить IP-адрес управления S1.
4. Настроить консольный доступ.
5. Настроить удалённый доступ по VTY.
6. Настроить IP-адрес PC-A.
7. Проверить сетевую связность.
8. Проверить удалённое управление с помощью Telnet.
9. Сохранить итоговую конфигурацию.

---

# Часть 1. Проверка исходной конфигурации коммутатора

## 1. Подключение к коммутатору

Для первоначальной настройки используется консольное подключение.

Консоль позволяет получить доступ к CLI устройства без предварительно настроенного IP-адреса и удалённого доступа.

Telnet или SSH на данном этапе использовать нельзя, поскольку для них сначала необходимо настроить сетевую доступность самого коммутатора.

Переход в привилегированный режим:

```text
Switch> enable
Switch#
```

---

## 2. Проверка текущей конфигурации

Для просмотра текущей конфигурации использована команда:

```text
show running-config
```

После начала настройки имя коммутатора было изменено на:

```text
S1
```

---

## 3. Проверка версии Cisco IOS

Выполнена команда:

```text
show version
```

Получены следующие сведения:

```text
Cisco IOS Software, C2960 Software (C2960-LANBASEK9-M),
Version 15.0(2)SE4

Model number: WS-C2960-24TT-L

24 FastEthernet interfaces
2 Gigabit Ethernet interfaces
```

Таким образом, используемый коммутатор имеет:

- 24 интерфейса FastEthernet;
- 2 интерфейса Gigabit Ethernet;
- Cisco IOS версии `15.0(2)SE4`.

Образ Cisco IOS:

```text
flash:c2960-lanbasek9-mz.150-2.SE4.bin
```

# Часть 2. Настройка базовых параметров сетевых устройств

## 1. Настройка основных параметров S1

Переход в режим глобальной конфигурации:

```text
S1# configure terminal
S1(config)#
```

Отключён DNS lookup:

```text
S1(config)# no ip domain-lookup
```

Это предотвращает попытки устройства интерпретировать ошибочно введённые команды как имена узлов для DNS-разрешения.

Настроено имя устройства:

```text
S1(config)# hostname S1
```

Включено шифрование отображаемых паролей:

```text
S1(config)# service password-encryption
```

Настроен секретный пароль привилегированного режима:

```text
S1(config)# enable secret class
```

---

## 2. Настройка MOTD Banner

Настроено предупреждение при подключении к устройству:

```text
S1(config)# banner motd #Unauthorized access is strictly prohibited.#
```

При подключении пользователь получает сообщение:

```text
Unauthorized access is strictly prohibited.
```

---

## 3. Настройка консольного доступа

Выполнена настройка консольной линии:

```text
S1(config)# line console 0
S1(config-line)# password cisco
S1(config-line)# login
S1(config-line)# logging synchronous
```

Команда `password cisco` устанавливает пароль консольного доступа.

Команда `login` включает проверку установленного пароля при подключении.

Команда `logging synchronous` предотвращает ситуацию, когда системные сообщения визуально прерывают ввод команды в CLI.

---

## 4. Настройка SVI VLAN 1

Для удалённого управления коммутатором настроен виртуальный интерфейс VLAN 1:

```text
S1(config)# interface vlan 1
S1(config-if)# ip address 192.168.1.2 255.255.255.0
S1(config-if)# no shutdown
```

Проверка выполнена командой:

```text
show ip interface brief
```

После подключения PC-A результат для VLAN 1:

```text
Vlan1    192.168.1.2    YES manual    up    up
```

Интерфейс `Vlan1` имеет административный IP-адрес `192.168.1.2/24` и находится в состоянии `up/up`.

---

## 5. Проверка FastEthernet0/6

PC-A подключён к интерфейсу `FastEthernet0/6`.

После подключения:

```text
FastEthernet0/6    unassigned    YES manual    up    up
```

Состояние:

```text
Status:   up
Protocol: up
```

означает, что физическое и канальное соединение между PC-A и S1 работает.

---

## 6. Настройка VTY

Для удалённого подключения к CLI коммутатора настроены VTY-линии.

```text
S1(config)# line vty 0 4
S1(config-line)# password cisco
S1(config-line)# login
```

Также настроены VTY 5–15:

```text
S1(config)# line vty 5 15
S1(config-line)# password cisco
S1(config-line)# login
```

Проверка:

```text
show running-config | section line vty
```

Результат:

```text
line vty 0 4
 password 7 0822455D0A16
 login
line vty 5 15
 password 7 0822455D0A16
 login
```

Таким образом, для удалённого доступа настроены VTY-линии `0–15`.

---

## 7. Настройка PC-A

На PC-A настроены следующие параметры:

```text
IP address: 192.168.1.10
Subnet mask: 255.255.255.0
```

PC-A и интерфейс управления S1 находятся в одной сети:

```text
192.168.1.0/24
```

## 3. Проверка удалённого управления через Telnet

С PC-A выполнено подключение:

```text
telnet 192.168.1.2
```

Результат:

```text
Trying 192.168.1.2 ...Open
Unauthorized access is strictly prohibited.

User Access Verification

Password:
```

После ввода пароля `cisco` получен пользовательский режим:

```text
S1>
```

Затем выполнена команда:

```text
S1> enable
Password:
```

После ввода секретного пароля получен привилегированный режим:

```text
S1#
```

Удалённый доступ к коммутатору работает.

> Для проверки удалённого доступа в соответствии с заданием использовался Telnet.

---

## 4. Сохранение конфигурации

После завершения настройки конфигурация сохранена в NVRAM:

```text
S1# copy running-config startup-config
```

# Ответы на вопросы лабораторной работы

### Почему для первоначальной настройки используется консольное подключение?

Консольное подключение не требует предварительно настроенного IP-адреса, VTY-линий или удалённого доступа. Поэтому через консоль можно получить доступ к CLI устройства с исходной конфигурацией.

---

### Сколько интерфейсов FastEthernet имеется на Cisco 2960?

**24 интерфейса FastEthernet.**

---

### Сколько интерфейсов Gigabit Ethernet имеется на Cisco 2960?

**2 интерфейса Gigabit Ethernet.**

---

### Каков диапазон VTY-линий?

```text
0–15
```

В конфигурации:

```text
line vty 0 4
line vty 5 15
```

---

### Почему при просмотре startup-config может появляться сообщение об отсутствии конфигурации?

Потому что в NVRAM ещё не сохранена загрузочная конфигурация `startup-config`.

---

### Был ли первоначально назначен IP-адрес VLAN 1?

Нет. В ходе лабораторной работы интерфейсу VLAN 1 был назначен адрес:

```text
192.168.1.2/24
```

---

### Какое состояние получил VLAN 1 после настройки и подключения PC-A?

```text
Vlan1    192.168.1.2    YES manual    up    up
```

---

### Какая версия Cisco IOS используется?

```text
Cisco IOS 15.0(2)SE4
```

---

### Как называется файл образа Cisco IOS?

```text
2960-lanbasek9-mz.150-2.SE4.bin
```

---

### В каком состоянии находится FastEthernet0/6 после подключения PC-A?

```text
FastEthernet0/6    unassigned    YES manual    up    up
```

Интерфейс работает.

---

### Для чего нужна команда `login`?

Команда `login` включает проверку пароля, настроенного для соответствующей Console или VTY-линии.

---

### Зачем настраивать пароль VTY?

VTY используется для удалённых CLI-сессий. Настройка пароля и команды `login` ограничивает удалённый доступ к коммутатору.

---

### Что необходимо сделать, чтобы пароли не передавались по сети в открытом виде?

Для удалённого управления следует использовать **SSH вместо Telnet**, поскольку SSH шифрует передаваемые данные.
