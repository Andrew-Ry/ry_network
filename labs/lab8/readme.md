# Лабораторная работа — Конфигурация безопасности коммутатора

## Цель работы

Настроить сеть с маршрутизатором R1, коммутаторами S1 и S2 и компьютерами PC-A и PC-B. Реализовать защиту уровня 2: отключение DTP, изоляцию неиспользуемых портов, Port Security, DHCP snooping, PortFast и BPDU Guard.

Работа выполнена в Cisco Packet Tracer. Проверка связности завершена успешно по результатам проверки исполнителем.

## Топология и адресация

Соединения устройств:

- R1 G0/0/1 — S1 Fa0/5.
- S1 Fa0/1 — S2 Fa0/1.
- PC-A — S1 Fa0/6.
- PC-B — S2 Fa0/18.

| Устройство | Интерфейс | IP-адрес | Маска |
|---|---|---|---|
| R1 | G0/0/1 | 192.168.10.1 | 255.255.255.0 |
| R1 | Loopback0 | 10.10.1.1 | 255.255.255.0 |
| S1 | VLAN 10 | 192.168.10.201 | 255.255.255.0 |
| S2 | VLAN 10 | 192.168.10.202 | 255.255.255.0 |
| PC-A | FastEthernet0 | 192.168.10.10, DHCP | 255.255.255.0 |
| PC-B | FastEthernet0 | 192.168.10.11, DHCP | 255.255.255.0 |

Шлюз для ПК — 192.168.10.1. Адреса ПК приведены по полученным DHCP-арендам.

## Настройка R1 и базовых параметров коммутаторов

На R1 настроен и включён G0/0/1 с адресом 192.168.10.1/24. Проверка `show ip interface brief` показала состояние `up/up`.

Настроен DHCP-пул Students для сети 192.168.10.0/24 со шлюзом 192.168.10.1. Из выдачи исключены адреса 192.168.10.1–192.168.10.9 и 192.168.10.201–192.168.10.202. После настройки DHCP компьютеры получили адреса .10 и .11. Loopback0 с адресом 10.10.1.1/24 использован для проверки доступа в другую IP-сеть.

На коммутаторах заданы имена S1 и S2, отключён DNS-поиск, настроены описания используемых физических портов, баннер и защита доступа паролями. Для управления назначены адреса SVI VLAN 10. Для связи коммутаторов с другими сетями предусмотрен шлюз `ip default-gateway 192.168.10.1`.

## Настройка VLAN и портов

На коммутаторах настроены VLAN:

| VLAN | Имя | Назначение |
|---|---|---|
| 10 | Management | Управление и подключение устройств по условиям лабораторной |
| 333 | Native | Native VLAN межкоммутаторного trunk |
| 999 | ParkingLot | Неиспользуемые порты |

Fa0/1 между S1 и S2 настроены в статическом режиме trunk с native VLAN 333. Командой `switchport nonegotiate` отключён DTP.

Проверка `show interfaces trunk` на S2 показала:

```text
Port        Mode  Encapsulation  Status    Native vlan
Fa0/1       on    802.1q         trunking  333

Vlans allowed and active: 1,10,333,999
Vlans in spanning tree forwarding state: 1,10,333,999
```

На S1 порты Fa0/5 и Fa0/6 назначены портами доступа VLAN 10. На S2 в VLAN 10 назначен Fa0/18. Остальные физические порты, кроме межкоммутаторных Fa0/1, переведены в VLAN 999 и административно отключены командой `shutdown`.

Проверка `show interfaces status` на S1 подтвердила состояние `connected` на используемых портах и `disabled` на неиспользуемых. Проверка `show vlan brief` на S2 подтвердила имена VLAN и назначение портов.

## Port Security

Перед настройкой на S1 Fa0/6 зафиксированы значения по умолчанию:

| Параметр | Значение |
|---|---|
| Port Security | Disabled |
| Maximum MAC Addresses | 1 |
| Violation Mode | Shutdown |
| Aging Time | 0 минут, старение отключено |
| Aging Type | Absolute |
| SecureStatic Address Aging | Disabled |
| Sticky MAC Address Learning | Disabled |

На S1 Fa0/6 включена защита с максимумом 3 MAC-адреса, режимом `restrict` и временем старения 60 минут. В этом режиме кадры от неизвестных MAC сверх лимита отбрасываются, нарушения учитываются, порт продолжает работать.

Проверка показала `Enabled`, `Secure-up`, один изученный MAC `0002.4ACB.7B1A` в VLAN 10 и нулевой счётчик нарушений.

По заданию требовалось старение по неактивности. Однако команда:

```text
switchport port-security aging type inactivity
```

была отклонена используемым устройством Packet Tracer с сообщением `% Invalid input detected`. Поэтому сохранён доступный тип `Absolute` с временем 60 минут. Это ограничение используемого стенда и отклонение от требования задания.

На S2 Fa0/18 настроены максимум 2 MAC-адреса, режим `protect`, sticky-обучение и время старения 60 минут. Режим `protect` отбрасывает кадры от неизвестных MAC сверх лимита без отключения порта.

В текущей конфигурации S2 появилась запись:

```text
switchport port-security mac-address sticky 0004.9AB9.27AC
```

Таким образом, MAC PC-B автоматически изучен и добавлен в running-config.

## DHCP snooping

На S2 включён DHCP snooping глобально и для VLAN 10. Fa0/1 объявлен доверенным, поскольку через него поступают ответы DHCP-сервера R1. Клиентский Fa0/18 оставлен недоверенным, для него установлен лимит 5 DHCP-пакетов в секунду.

После включения защиты первоначально возник отказ обновления DHCP-адреса. Для устранения были предложены обработка Option 82 на R1 командой `ip dhcp relay information trust-all` либо, при её недоступности, отключение добавления Option 82 на S2 командой `no ip dhcp snooping information option`. Конкретный применённый вариант не зафиксирован в предоставленных выводах.

После устранения проблемы DHCP снова заработал. Проверка `show ip dhcp snooping binding` показала:

```text
MacAddress          IpAddress       Lease(sec) Type           VLAN Interface
00:04:9A:B9:27:AC   192.168.10.11   0          dhcp-snooping  10   FastEthernet0/18
Total number of bindings: 1
```

Запись подтверждает обучение привязки IP и MAC PC-B к VLAN 10 и Fa0/18. Значение Lease(sec) приведено как в фактическом выводе Packet Tracer.

## PortFast и BPDU Guard

На используемых портах доступа включён PortFast: S1 Fa0/5 и Fa0/6, S2 Fa0/18. Он позволяет сразу перейти к передаче трафика, минуя стандартное ожидание STP.

На клиентских портах S1 Fa0/6 и S2 Fa0/18 включён BPDU Guard. При получении BPDU такой порт должен перейти в состояние err-disabled. На межкоммутаторных Fa0/1 эти функции не настраивались.

Вывод `show spanning-tree interface ... detail` на S1 подтвердил PortFast и состояние forwarding. Наличие BPDU Guard на клиентских портах подтверждено текущими конфигурациями:

```text
spanning-tree portfast
spanning-tree bpduguard enable
```

Проверка с намеренной подачей BPDU не выполнялась в рамках предоставленных результатов.

## Проверка связности

PC-A получил 192.168.10.10/24, PC-B — 192.168.10.11/24, оба со шлюзом 192.168.10.1. Предоставленный вывод ping с PC-B до R1 содержит 4 ответа из 4, потери 0%.

Выполнителю предложены проверки доступности маршрутизатора, SVI обоих коммутаторов, связи между ПК и Loopback0:

```text
ping 192.168.10.1
ping 192.168.10.201
ping 192.168.10.202
ping 192.168.10.10
ping 192.168.10.11
ping 10.10.1.1
```

Адрес собственного ПК исключается из проверки сквозной связности. Исполнитель подтвердил, что проверяемые IP-адреса отвечают. Полные выводы остальных ping в переписке не предоставлены.

## Ответы на вопросы для повторения

### Почему у sticky MAC отсутствует оставшееся время старения

На Catalyst 2960 старение sticky secure MAC по таймеру Port Security Aging не поддерживается. Поэтому для такого адреса отображается прочерк вместо оставшегося времени, даже при настроенном `aging time 60`. Чтобы sticky-записи сохранялись после перезагрузки, running-config необходимо сохранить в startup-config.

### Почему после загрузки конфигурации PC-B может не получить адрес по DHCP

В конфигурации могут сохраниться sticky MAC прежних устройств. Если они занимают все разрешённые места, а MAC подключённого PC-B отличается, режим protect отбрасывает его кадры, в том числе DHCP-запросы. Нужно удалить устаревшие sticky-записи и дать порту изучить MAC текущего ПК.

Само наличие sticky-записи не означает обязательный отказ DHCP: если MAC совпадает или есть свободное место для обучения, выдача адреса возможна.

### Чем Absolute отличается от Inactivity

Absolute удаляет динамический защищённый MAC по истечении заданного времени независимо от активности. Inactivity удаляет его после заданного периода отсутствия трафика от этого MAC. Для sticky MAC на используемой платформе эти таймеры не применяются.

## Результат работы

Настроены VLAN, trunk, порты доступа и изоляция неиспользуемых портов. Реализованы Port Security, DHCP snooping, PortFast и BPDU Guard. DHCP выдаёт адреса, таблица snooping содержит привязку PC-B, связность подтверждена исполнителем. Требование Inactivity на S1 заменено на Absolute из-за отклонения команды в Packet Tracer.

Перед сдачей необходимо сохранить конфигурацию на R1, S1 и S2 командой `copy running-config startup-config` и сохранить проект Packet Tracer в файл `.pkt`. Подтверждение сохранения в предоставленных выводах отсутствует.
