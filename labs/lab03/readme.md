# Лабораторная работа
# Настройка IPv6-адресов на сетевых устройствах

## 1. Цель работы

Настроить IPv6-адреса на маршрутизаторе, коммутаторе и двух компьютерах; проверить автоматическое получение адресов через SLAAC и ручную адресацию; проверить связь внутри локальной сети и между двумя сетями с помощью `ping` и `tracert`.

Работа выполнена в Cisco Packet Tracer. Использованы маршрутизатор Cisco 4321, коммутатор Cisco 2960 и два ПК. В методичке указан Cisco 4221, но в используемой среде был выбран доступный 4321 с интерфейсами G0/0/0 и G0/0/1.

## 2. Топология

```text
PC-A → S1 → R1 → PC-B

PC-A NIC ── Fa0/6 [ S1 ] Fa0/5 ── G0/0/1 [ R1 ] G0/0/0 ── NIC PC-B
             VLAN 2                 │              │
                    2001:DB8:ACAD:1::/64     2001:DB8:ACAD:A::/64
```

PC-A и интерфейс управления S1 находятся в сети `2001:DB8:ACAD:1::/64`. PC-B находится в сети `2001:DB8:ACAD:A::/64`. Обмен между этими сетями выполняет R1. S1 передаёт кадры внутри VLAN2, а его SVI используется для обращения к самому коммутатору.

## 3. Итоговая таблица адресации

В таблице указана окончательная конфигурация после перехода ПК на статические адреса.

| Устройство | Интерфейс | IPv6-адрес | Префикс | Link-local адрес | Шлюз по умолчанию |
|---|---|---|---|---|---|
| R1 | G0/0/0, к PC-B | `2001:DB8:ACAD:A::1` | /64 | `FE80::1` | — |
| R1 | G0/0/1, к S1 | `2001:DB8:ACAD:1::1` | /64 | `FE80::1` | — |
| S1 | Vlan2, управление | `2001:DB8:ACAD:1::B` | /64 | `FE80::B` | — |
| PC-A | FastEthernet0 | `2001:DB8:ACAD:1::3` | /64 | `FE80::201:63FF:FE63:35E9` | `FE80::1` |
| PC-B | FastEthernet0 | `2001:DB8:ACAD:A::3` | /64 | `FE80::205:5EFF:FEE0:9A44` | `FE80::1` |

Для S1 отдельный шлюз в исходной таблице не задан. Проверка его адреса управления выполнялась с PC-A из той же сети.

## 4. Базовая настройка устройств

Устройствам назначены имена R1 и S1. Базовая подготовка включает отключение DNS-поиска при ошибочном вводе команд, пароль привилегированного режима, шифрование отображаемых линейных паролей и предупреждающий баннер.

Ниже приведён сводный набор команд базовой настройки R1. Это оформленная последовательность, а не дословная выгрузка его `running-config`: полный базовый конфиг R1 в переписке не приводился. Значение `<пароль>` обозначает выбранный пароль.

```text
enable
configure terminal
hostname R1
no ip domain-lookup
enable secret <пароль>
service password-encryption
banner motd #Unauthorized access is strictly prohibited.#
end
```

Для S1 в ходе работы подтверждены имя, `enable secret`, `service password-encryption`, `no ip domain-lookup` и баннер:

```text
Unauthorized access is strictly prohibited.
```

Удалённый доступ на S1 настроен через SSH вместо Telnet; команды приведены в разделе 6.3.

## 5. Настройка IPv6 на R1

### 5.1. Адреса интерфейсов и маршрутизация

На каждом интерфейсе назначены глобальный IPv6-адрес и link-local адрес. Интерфейсы включены командой `no shutdown`.

```text
configure terminal
interface GigabitEthernet0/0/0
 ipv6 address 2001:DB8:ACAD:A::1/64
 ipv6 address FE80::1 link-local
 no shutdown
 exit
interface GigabitEthernet0/0/1
 ipv6 address 2001:DB8:ACAD:1::1/64
 ipv6 address FE80::1 link-local
 no shutdown
 exit
ipv6 unicast-routing
end
```

Команда `ipv6 unicast-routing` включила IPv6-маршрутизацию. В этой конфигурации R1 также отправляет объявления Router Advertisement (RA), по которым компьютеры могут получить сведения о префиксе и шлюзе для SLAAC. Статические маршруты между двумя сетями не понадобились: обе сети непосредственно подключены к R1.

### 5.2. Проверка интерфейсов

Фактический результат `show ipv6 interface brief` после настройки:

```text
GigabitEthernet0/0/0       [up/up]
    FE80::1
    2001:DB8:ACAD:A::1
GigabitEthernet0/0/1       [up/up]
    FE80::1
    2001:DB8:ACAD:1::1
Vlan1                    [administratively down/down]
    unassigned
```

Оба рабочих интерфейса находятся в состоянии `up/up`: физическое соединение и протокол линии работают.

Для просмотра подробностей использовалась команда:

```text
show ipv6 interface g0/0/0
```

После включения маршрутизации зафиксированы группы:

| Группа | Назначение |
|---|---|
| `FF02::1` | Все IPv6-узлы в локальном канале |
| `FF02::2` | Все IPv6-маршрутизаторы в локальном канале |
| `FF02::1:FF00:1` | Solicited-node multicast для адресов интерфейса, оканчивающихся на `::1`; используется при обнаружении соседей |

Эти группы появились автоматически. У `FE80::1` и `2001:DB8:ACAD:A::1` одинаковые последние 24 бита, поэтому им соответствует одна solicited-node группа.

## 6. Настройка S1

### 6.1. Отличия от методички

В исходном задании адрес управления S1 находится на VLAN1. В выполненной работе конфигурация изменена:

- SVI управления перенесён на VLAN2 с сохранением адресов `2001:DB8:ACAD:1::B/64` и `FE80::B`.
- Рабочие порты Fa0/5 и Fa0/6 переведены в VLAN2 и работают в режиме access.
- Неиспользуемые Fa0/1–4, Fa0/7–24 и Gi0/1–2 перенесены в VLAN3 с именем `UNUSED` и выключены командой `shutdown`.
- Для удалённого доступа на S1 настроен SSHv2 вместо Telnet.

Номер VLAN изменился, но IPv6-сеть осталась `2001:DB8:ACAD:1::/64`.

### 6.2. VLAN, порты и SVI

Сводная последовательность команд для полученной конфигурации:

```text
configure terminal
vlan 2
 exit
vlan 3
 name UNUSED
 exit
interface range FastEthernet0/5 - 6
 switchport mode access
 switchport access vlan 2
 no shutdown
 exit
interface range FastEthernet0/1 - 4
 switchport mode access
 switchport access vlan 3
 shutdown
 exit
interface range FastEthernet0/7 - 24
 switchport mode access
 switchport access vlan 3
 shutdown
 exit
interface range GigabitEthernet0/1 - 2
 switchport mode access
 switchport access vlan 3
 shutdown
 exit
interface Vlan1
 no ipv6 address
 exit
interface Vlan2
 ipv6 address FE80::B link-local
 ipv6 address 2001:DB8:ACAD:1::B/64
 no shutdown
end
```

При переносе сначала возникла ошибка пересечения подсетей: адрес `2001:DB8:ACAD:1::B/64` ещё оставался на Vlan1. После удаления IPv6-адресов с прежнего SVI удалось назначить адрес на Vlan2.

Фактически полученный фрагмент конфигурации:

```text
interface Vlan2
 no ip address
 ipv6 address FE80::B link-local
 ipv6 address 2001:DB8:ACAD:1::B/64
```

Строка `no ip address` означает отсутствие IPv4-адреса и не отменяет настройки IPv6.

Для проверки использовались команды:

```text
show interfaces status
show vlan brief
show ipv6 interface vlan 2
```

В промежуточной проверке неиспользуемые порты имели состояние `disabled` и VLAN3. Fa0/6 уже был `connected` в VLAN2, а Fa0/5 показывал `notconnect`, поскольку интерфейс R1 ещё не был включён. После настройки R1 связь через S1 подтверждена итоговыми проверками.

VLAN3 служит для размещения неиспользуемых портов. Командой `shutdown` выключены именно физические порты.

В методичке также предусмотрена проверка SDM командой `show sdm prefer` и, при необходимости, включение шаблона `sdm prefer dual-ipv4-and-ipv6 default` с перезагрузкой. В выполненной работе поддержка IPv6 на S1 была активирована; её работоспособность подтверждается назначенными адресами SVI и успешным ping.

### 6.3. SSH вместо Telnet

На S1 настроены доменное имя `S1.local`, пользователь `admin`, RSA-ключи длиной 2048 бит, локальная проверка пользователя на VTY 0–15 и только SSH версии 2. В лабораторной для пользователя использован пароль `cisco`.

```text
configure terminal
ip domain-name S1.local
username admin secret cisco
crypto key generate rsa
```

При запросе длины ключа введено `2048`. Устройство подтвердило генерацию:

```text
How many bits in the modulus [512]: 2048
% Generating 2048 bit RSA keys, keys will be non-exportable...[OK]
```

Затем настроены линии удалённого доступа:

```text
line vty 0 15
 login local
 transport input ssh
 exit
ip ssh version 2
end
```

При первоначальной проверке `show ip ssh` отображалась версия `1.99`. После этого выполнена команда `ip ssh version 2`, чтобы использовать только SSHv2. Отдельный результат подключения SSH-клиента в журнале работы не зафиксирован.

## 7. Настройка PC-A и PC-B

### 7.1. Проверка SLAAC

На каждом ПК в `Desktop → IP Configuration → IPv6` последовательно выбран режим `Auto Config`. Полученные адреса проверены командой `ipconfig`.

**PC-A — фактический результат:**

```text
Link-local IPv6 Address.........: FE80::201:63FF:FE63:35E9
IPv6 Address....................: 2001:DB8:ACAD:1:201:63FF:FE63:35E9
```

**PC-B — фактический результат:**

```text
Link-local IPv6 Address.........: FE80::205:5EFF:FEE0:9A44
IPv6 Address....................: 2001:DB8:ACAD:A:205:5EFF:FEE0:9A44
```

Оба ПК получили адреса из своих сетей с префиксом /64. R1 сообщил префиксы через RA, а ПК сформировали оставшуюся часть адреса самостоятельно. В этой работе использовался SLAAC; DHCPv6-сервер не настраивался.

На PC-B сначала был выбран режим Static без заданного глобального адреса. В `ipconfig` отображались link-local адрес и `IPv6 Address: ::`, хотя `ping FE80::1` уже проходил. После переключения на Auto Config появился адрес SLAAC. Таким образом, причина была в режиме настройки ПК.

### 7.2. Статическая адресация

После проверки SLAAC оба компьютера переведены в режим `Static` и настроены по таблице лабораторной.

| Параметр | PC-A | PC-B |
|---|---|---|
| IPv6 Address | `2001:DB8:ACAD:1::3` | `2001:DB8:ACAD:A::3` |
| Prefix Length | `64` | `64` |
| Default Gateway | `FE80::1` | `FE80::1` |

Проверка `ipconfig` подтвердила:

```text
PC-A
Link-local IPv6 Address.........: FE80::201:63FF:FE63:35E9
IPv6 Address....................: 2001:DB8:ACAD:1::3

PC-B
IPv6 Address....................: 2001:DB8:ACAD:A::3
```

Одинаковый адрес шлюза `FE80::1` относится к разным интерфейсам R1: для PC-A это G0/0/1, для PC-B — G0/0/0.

## 9. Сохранение конфигураций

После завершения настройки и проверок конфигурации обоих устройств сохранены:

```text
R1# copy running-config startup-config
S1# copy running-config startup-config
```

На запрос `Destination filename [startup-config]?` используется имя по умолчанию. Допустимое сокращение команды — `copy run start`.

Команда сохраняет текущую конфигурацию как стартовую, чтобы она использовалась после перезагрузки. Сохранение на обоих устройствах подтверждено по завершении практической части.

## 10. Ответы на вопросы

### Вопросы по ходу работы

**Какие группы многоадресной рассылки назначены интерфейсу R1 G0/0/0?**

После включения IPv6-маршрутизации зафиксированы `FF02::1`, `FF02::2` и `FF02::1:FF00:1`. Это группы всех IPv6-узлов, всех IPv6-маршрутизаторов и группа обнаружения соседей для адресов данного интерфейса. Группа `FF02::2` связана с работой устройства как IPv6-маршрутизатора.

**Назначен ли индивидуальный IPv6-адрес сетевой карте PC-B?**

При первоначальной проверке был только link-local адрес `FE80::205:5EFF:FEE0:9A44`, который тоже является индивидуальным адресом. Глобального адреса ещё не было: строка `IPv6 Address` содержала `::`. После включения Auto Config появился `2001:DB8:ACAD:A:205:5EFF:FEE0:9A44`.

**Почему PC-B получил глобальный префикс и идентификатор подсети, настроенные на R1?**

R1 сообщил компьютеру префикс `2001:DB8:ACAD:A::/64` в объявлении RA. PC-B использовал его для SLAAC и самостоятельно сформировал остальную часть адреса. Поэтому начало адреса PC-B совпадает с сетью интерфейса R1, к которому он подключён.

### Контрольный вопрос 1

**Почему обоим интерфейсам Ethernet на R1 можно назначить один и тот же локальный адрес канала FE80::1?**

Так как у каждого порта своя локальная сеть, одинаковые локальные IPv6-адреса могут использоваться в разных локальных сетях.

### Контрольный вопрос 2

**Какой идентификатор подсети (Subnet ID) в адресе `2001:DB8:ACAD::AAAA:1234/64`?**

**Subnet ID = `0000`.**

Полная запись адреса:

```text
2001:0DB8:ACAD:0000:0000:0000:AAAA:1234/64
               ↑
          Subnet ID
```

В принятой в задании схеме с глобальным префиксом /48 и подсетями /64 идентификатор подсети — четвёртый хекстет. В данном адресе он равен `0000`.

## 11. Вывод

В ходе работы настроены IPv6-адреса R1, S1 и двух ПК. Проверено автоматическое получение адресов через SLAAC, после чего компьютерам назначены статические адреса по таблице задания. На S1 интерфейс управления перенесён на VLAN2, рабочие порты включены в этот VLAN, неиспользуемые порты помещены в VLAN3 UNUSED и выключены. Удалённый доступ S1 настроен на SSHv2.

Все четыре проверки ping завершились без потерь. Трассировка от PC-A до PC-B показала прохождение через R1 и достижение конечного узла. Это подтверждает работоспособность локальных соединений и IPv6-маршрутизации между сетями `2001:DB8:ACAD:1::/64` и `2001:DB8:ACAD:A::/64`. Конфигурации R1 и S1 сохранены.
