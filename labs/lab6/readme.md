# Лабораторная работа по STP

Развертывание коммутируемой сети с резервными каналами в Cisco Packet Tracer.

В работе собрана сеть из трех коммутаторов, проверена IP-связность, определен корневой мост и исследовано влияние стоимости пути и идентификатора порта на выбор STP. Корневым стал S1. Изменение стоимости позволило перенести блокировку между S3 и S2, а включение параллельных соединений показало выбор по идентификатору порта отправителя BPDU.

## 1. Топология и адресация

Использованы три коммутатора Cisco 2960: S1, S2 и S3. Между каждой парой проложены два Ethernet-соединения.

| Первый конец | Второй конец |
|---|---|
| S1 Fa0/1 | S2 Fa0/1 |
| S1 Fa0/2 | S2 Fa0/2 |
| S1 Fa0/3 | S3 Fa0/3 |
| S1 Fa0/4 | S3 Fa0/4 |
| S2 Fa0/3 | S3 Fa0/1 |
| S2 Fa0/4 | S3 Fa0/2 |

| Коммутатор | Интерфейс управления | IP-адрес | Маска |
|---|---|---|---|
| S1 | Vlan1 | 192.168.1.1 | 255.255.255.0 |
| S2 | Vlan1 | 192.168.1.2 | 255.255.255.0 |
| S3 | Vlan1 | 192.168.1.3 | 255.255.255.0 |

Физические порты не требуют IP-адресов: они коммутируют кадры второго уровня. IP назначен логическому интерфейсу Vlan1 для обращения к самому коммутатору. STP работает без IP-адресации.

## 2. Базовая настройка

### Общий блок для всех коммутаторов

Команды вводятся из привилегированного режима с приглашением вида `S1#`. Блок одинаковый для S1, S2 и S3 и не изменяет их имена и IP-адреса.

```text
configure terminal
no ip domain-lookup
enable secret class
service password-encryption
banner motd #Unauthorized access is prohibited!#
line console 0
password cisco
login
logging synchronous
exit
line vty 0 15
password cisco
login
exit
end
copy running-config startup-config
```

На запрос `Destination filename [startup-config]?` нужно нажать Enter.

| Команда | Назначение |
|---|---|
| `no ip domain-lookup` | Отключает DNS-поиск при ошибочном вводе команды |
| `enable secret class` | Задает защищенный пароль привилегированного режима |
| `service password-encryption` | Скрывает открытые пароли в конфигурации обратимым кодированием; это не равно стойкому шифрованию |
| `banner motd` | Показывает предупреждение о запрете несанкционированного доступа |
| `line console 0` | Выбирает консольную линию |
| `line vty 0 15` | Выбирает линии удаленного терминального доступа |
| `password cisco` и `login` | Назначают пароль линии и включают его проверку |
| `logging synchronous` | Не дает служебным сообщениям разрывать вводимую в консоли строку |
| `copy running-config startup-config` | Сохраняет текущую конфигурацию для загрузки после перезапуска |

### Индивидуальные имена и IP-адреса

Пример для S3:

```text
configure terminal
hostname S3
interface vlan 1
ip address 192.168.1.3 255.255.255.0
no shutdown
end
copy running-config startup-config
```

Для S1 используются имя S1 и адрес 192.168.1.1, для S2 — S2 и 192.168.1.2. В ходе работы на S3 повторно заданы правильные имя и адрес после случайной вставки параметров S1.

### Проверка связности

```text
show ip interface brief
```

Для Vlan1 требуется рабочее состояние `up/up`. Одного назначения адреса недостаточно: интерфейс должен быть включен, а VLAN должна иметь работающий порт с подходящим состоянием STP.

На S1 выполнены:

```text
ping 192.168.1.2
ping 192.168.1.3
```

На S2 выполнен:

```text
ping 192.168.1.3
```

Первоначально ping завершался `.....` и результатом 0/5. Обнаружено, что Vlan1 не был включен. После `no shutdown` связь появилась. В одном из промежуточных тестов S1 → S3 получен ответ `..!!!`, то есть 3/5. После повторных проверок подтверждено прохождение ping.

Точка означает истечение времени ожидания, восклицательный знак — успешный ответ. Первоначальные потери могут сопровождать ARP-разрешение и сходимость STP; точная причина двух потерь отдельным измерением не устанавливалась.

**Ответы на вопросы части 1:**

| Проверка | Результат по выполненной работе |
|---|---|
| S1 → S2 | Эхо-запрос проходит |
| S1 → S3 | Эхо-запрос проходит |
| S2 → S3 | Эхо-запрос проходит |

## 3. Подготовка первого эксперимента STP

На всех трех коммутаторах отключены физические порты, Fa0/1–Fa0/4 настроены как trunk, затем включены только Fa0/2 и Fa0/4:

```text
configure terminal
interface range fastEthernet 0/1 - 24
shutdown
exit
interface range gigabitEthernet 0/1 - 2
shutdown
exit
interface range fastEthernet 0/1 - 4
switchport mode trunk
exit
interface fastEthernet 0/2
no shutdown
exit
interface fastEthernet 0/4
no shutdown
end
```

Диапазон FastEthernet не включает GigabitEthernet, поэтому гигабитные порты выбираются отдельно. Команда `interface range` только выбирает интерфейсы; отключает их следующая команда `shutdown`.

Trunk позволяет передавать несколько VLAN по одному соединению. Здесь он настроен по условию задания. Для единственной VLAN 1 эксперимент STP возможен и через access-порты в этой VLAN. Trunk и STP выполняют разные задачи: первый переносит VLAN, второй предотвращает петли.

После включения остался треугольник:

```text
          S1
         /  \
        /    \
       S2----S3
```

На каждом устройстве выполнена команда `show spanning-tree` после ожидания сходимости.

## 4. Выбор корневого моста

### Идентификаторы коммутаторов

| Коммутатор | Приоритет с учетом VLAN 1 | MAC из Bridge ID |
|---|---|---|
| S1 | 32769 | 0002.160B.A729 |
| S2 | 32769 | 000A.4183.C9EB |
| S3 | 32769 | 00D0.FFE3.7C99 |

Значение 32769 получается как 32768 — базовый приоритет — плюс 1, номер VLAN. При одинаковом приоритете корнем становится устройство с наименьшим MAC-адресом. В нашей сети это S1.

На S1 получена строка `This bridge is the root`. На всех устройствах Root ID содержит адрес S1 — `0002.160B.A729`.

Root ID описывает выбранный корень, Bridge ID — локальный коммутатор. Роль порта `Root` означает путь к корню и сама по себе не делает коммутатор корневым.

### Роли портов до изменения стоимости

| Коммутатор | Fa0/1 | Fa0/2 | Fa0/3 | Fa0/4 |
|---|---|---|---|---|
| S1 | Отключен | Desg FWD | Отключен | Desg FWD |
| S2 | Отключен | Root FWD | Отключен | Desg FWD |
| S3 | Отключен | Altn BLK | Отключен | Root FWD |

Стоимость пути до S1 на S2 и S3 равна 19. На соединении S2–S3 преимущество получает S2 с меньшим Bridge ID, поэтому блокируется S3 Fa0/2.

### Ответы на вопросы части 2

1. **Какой коммутатор является корневым мостом?** S1.
2. **Почему выбран именно он?** У всех одинаковый приоритет 32769, а MAC-адрес S1 наименьший; следовательно, его BID наименьший.
3. **Какие порты являются корневыми?** S2 Fa0/2 и S3 Fa0/4. У самого S1 корневого порта нет.
4. **Какие порты являются назначенными?** S1 Fa0/2, S1 Fa0/4 и S2 Fa0/4.
5. **Какой альтернативный порт заблокирован?** S3 Fa0/2.
6. **Почему заблокирован этот порт?** S2 и S3 имеют одинаковую стоимость до корня — 19. При сравнении BID выигрывает S2. Его Fa0/4 становится назначенным, а противоположный S3 Fa0/2 — альтернативным заблокированным. Это разрывает петлю.

## 5. Изменение стоимости пути

На S3 стоимость корневого порта Fa0/4 для VLAN 1 уменьшена с 19 до 18:

```text
configure terminal
interface fastEthernet 0/4
spanning-tree vlan 1 cost 18
end
```

Изменена метрика STP на конкретном интерфейсе для VLAN 1. Скорость кабеля и порта не изменялась.

### Полученный результат

| Коммутатор | Порт | До изменения | После сходимости |
|---|---|---|---|
| S2 | Fa0/2 | Root FWD, cost 19 | Root FWD, cost 19 |
| S2 | Fa0/4 | Desg FWD | Altn BLK |
| S3 | Fa0/4 | Root FWD, cost 19 | Root FWD, cost 18 |
| S3 | Fa0/2 | Altn BLK | Desg FWD |

На S3 сначала наблюдалось `Fa0/2 Desg LRN`, затем `Desg FWD`. Это нормальный переход из обучения в пересылку. На S2 подтверждено `Fa0/4 Altn BLK`.

**Почему STP поменял назначенный и заблокированный порты местами?** После изменения S3 объявляет стоимость до корня 18, а S2 — 19. На соединении S2–S3 назначенным становится порт S3: стоимость сравнивается раньше BID. Порт S2 на этом соединении блокируется для предотвращения петли.

S2 сохраняет прямой корневой порт Fa0/2: прямой путь стоит 19, а путь через S3 — 19 + 18 = 37. Корневым мостом остается S1.

### Возврат исходной стоимости

На S3 выполнено:

```text
configure terminal
interface fastEthernet 0/4
no spanning-tree vlan 1 cost
end
```

Команда отменяет ручную стоимость на выбранном порту для VLAN 1. Автоматическая стоимость FastEthernet 100 Мбит/с возвращается к 19. STP и интерфейс остаются включенными.

После сходимости на S3 подтверждено:

```text
Fa0/2   Altn BLK   19
Fa0/4   Root FWD   19
```

## 6. Выбор между параллельными соединениями

На всех трех коммутаторах включены Fa0/1 и Fa0/3. Использованный блок повторно включает весь диапазон Fa0/1–Fa0/4; уже работающие порты остаются включенными:

```text
configure terminal
interface range fastEthernet 0/1 - 4
no shutdown
end
```

Проверка `show ip interface brief` подтвердила `up/up` для Fa0/1–Fa0/4 на S2 и S3. После сходимости получены следующие роли.

| Коммутатор | Fa0/1 | Fa0/2 | Fa0/3 | Fa0/4 |
|---|---|---|---|---|
| S1 | Desg FWD* | Desg FWD* | Desg FWD* | Desg FWD* |
| S2 | Root FWD | Altn BLK | Desg FWD | Desg FWD |
| S3 | Altn BLK | Altn BLK | Root FWD | Altn BLK |

Роли S2 и S3 подтверждены финальными выводами команд. Строка S1 со звездочками следует из топологии и роли S1 как корня; отдельный финальный вывод всех четырех портов S1 в переписке не приводился.

### Ответы на вопросы части 4

**Какой корневой порт выбран на каждом некорневом коммутаторе?**

- На S2 — Fa0/1.
- На S3 — Fa0/3.

**Почему выбраны именно эти порты?**

Каждый коммутатор имеет два прямых соединения с S1. Стоимость прямых путей равна 19, корень и BID отправителя BPDU совпадают. Поэтому сравнивается идентификатор отправляющего порта S1: приоритет порта и его номер.

| Получатель | Сравниваемые порты S1 | Выигравший Port ID | Выбранный локальный порт |
|---|---|---|---|
| S2 | Fa0/1 и Fa0/2 | 128.1 | S2 Fa0/1 |
| S3 | Fa0/3 и Fa0/4 | 128.3 | S3 Fa0/3 |

Приоритеты всех этих портов равны 128, поэтому решает меньший номер порта отправителя. Вручную приоритет порта в этом эксперименте не изменялся.

Меньший номер локального порта сам по себе не гарантирует победу: на S3 Fa0/1 проигрывает Fa0/3, поскольку путь через S2 стоит 38, а прямой путь к S1 — 19.

## 7. Ответы на вопросы для повторения

1. **Какое значение STP использует первым после выбора корневого моста для выбора порта?** Суммарную стоимость пути до корня. Предпочтителен путь с меньшей стоимостью.
2. **Если первое значение на двух портах одинаково, какое следующее значение используется?** Bridge ID коммутатора, отправившего BPDU. Выигрывает меньший BID.
3. **Если оба значения равны, что сравнивается дальше?** Port ID отправляющего порта: сначала его приоритет, затем номер. Выигрывает меньший идентификатор.

Для полноты: если совпадает и Port ID отправителя, последним критерием выбора корневого порта служит локальный Port ID получателя. В нашей топологии до этого сравнения дело не доходило.

## 8. Как читать вывод show spanning-tree

| Поле | Значение |
|---|---|
| `VLAN0001` | Дерево для VLAN 1 |
| `protocol ieee` | Классический STP в показанном экземпляре VLAN |
| `Root ID` | Идентификатор корневого моста |
| `Bridge ID` | Идентификатор локального коммутатора |
| `This bridge is the root` | Локальный коммутатор является корнем |
| `Root ID Cost` | Суммарная стоимость выбранного пути до корня |
| `Root ID Port` | Локальный порт выбранного пути до корня |
| `Root` | Корневой порт некорневого коммутатора |
| `Desg` | Назначенный порт сегмента |
| `Altn` | Альтернативный путь |
| `BLK` | Обычный трафик заблокирован, обработка BPDU продолжается |
| `LIS` | Listening: обработка BPDU без изучения MAC и пересылки данных |
| `LRN` | Learning: изучение MAC без пересылки обычного трафика |
| `FWD` | Forwarding: пересылка трафика |
| `Cost` в строке интерфейса | Собственная стоимость этого порта для VLAN |
| `Prio.Nbr`, например 128.4 | Приоритет локального порта 128 и номер 4 |
| `P2p` | Соединение «точка-точка» |

Hello Time 2 секунды — интервал формирования корнем конфигурационных BPDU. Max Age 20 секунд — параметр срока актуальности информации STP. Forward Delay 15 секунд используется для каждого из этапов Listening и Learning; обычный переход через оба занимает около 30 секунд. При некоторых изменениях топологии ожидание может быть дольше.

`Aging Time` относится к сроку хранения динамических записей MAC-таблицы. В приведенных выводах показано 20; это наблюдаемое значение, а не универсальная настройка по умолчанию.

## 9. Разобранные ошибки и полезные команды

| Наблюдение | Что оно означает | Действие |
|---|---|---|
| Vlan1 не включен, ping не проходит | Логический интерфейс управления отключен | `interface vlan 1`, затем `no shutdown` |
| `administratively down/down` | Порт отключен настройкой | `no shutdown` на нужном интерфейсе |
| `down/down` | Порт административно включен, но физический канал не поднят | Проверить кабель и включение второго конца |
| `up/up`, но STP показывает BLK | Канал исправен, STP блокирует обычный трафик | Это нормальное резервирование |
| `unassigned` на FastEthernet | У физического порта нет IP | Для портов этой L2-сети это нормально |
| `Desg LIS` или `Desg LRN` | Переходное состояние STP | Дождаться сходимости |

Во время включения параллельных соединений разбиралось отсутствие рабочего канала Fa0/1. После настройки получено `up/up` на всех четырех используемых портах S2 и S3.

Команда `do` позволяет выполнить просмотр прямо из режима настройки:

```text
do show spanning-tree
do show ip interface brief
```

Из привилегированного режима префикс `do` не нужен:

```text
show spanning-tree
show ip interface brief
show interfaces status
show cdp neighbors
```

Последние две команды полезны для диагностики; их результаты в этой работе не предоставлялись.

## 10. Сохранение и результат

Для сохранения настроек на каждом коммутаторе используется:

```text
copy running-config startup-config
```

После этого проект Packet Tracer сохраняется отдельно через Ctrl+S. Сохранение конфигурации устройства и сохранение файла проекта — отдельные действия.

В ходе работы базовый блок настройки был предоставлен для всех устройств, после чего выполнение подтверждено пользователем. Полные выводы `show running-config` не собирались. Сброс конфигурации и перезагрузка, упомянутые в методичке как подготовительные действия, отдельными выводами не подтверждались.

Практические наблюдения показали: S1 выбран корнем по минимальному BID; стоимость пути имеет преимущество перед BID соседа; при равенстве стоимости и BID отправителя выбор определяется его Port ID. Резервные физические соединения сохраняются, а STP блокирует часть портов для обычного трафика, устраняя петли.
